NetComposer / Supplier spec

A Supplier publishes one index file and one manifest per sound. This page describes the fields exactly as musicmatter.art publishes them today (format version 0.1). Anything not yet in use there is marked PROPOSED.

Index: netcomposer.json

Served at the site root, e.g. musicmatter.art/netcomposer.json.

Manifest: one per sound

At the URL in offerings[].manifest, e.g. /sounds/<name>.nc.json. Field counts are from the 2026-10-17 validation of all 1356 live manifests; sub-keys are from the same published files.

PROPOSED

  • Minimum per manifest (PROPOSED). title, creator, audio, sha256, size_bytes, and license unless the index has default_license. Everything else is optional. The validator checks this minimum.
  • License identifiers (PROPOSED). SPDX-style ids: CC0-1.0, CC-BY-3.0, CC-BY-4.0, CC-BY-SA-3.0, CC-BY-SA-4.0, PDM-1.0. Any NC, ND, Sampling+ or custom license is rejected.
  • Checksums (PROPOSED as required). sha256 and size_bytes must match the audio bytes served. Validation runs will check them; today the validator does.

The fields describing the sound (type, chords, register, key, arpeggio) are what let a Performer choose musically without listening first. A Supplier of other kinds of sound may leave them out.

Validate

tools/validate_supplier.py (Python standard library only): python3 validate_supplier.py <index_url> [--sample 25] [--all-manifests] [--json report.json]. It checks the index, the manifests (parse, license, minimum fields, audio path matches the index) and a sample of audio files (sha256 and size). Exit code 0 means valid.
